# Roadmap

| Stage | Goal | Description | Status | Main Limitations |
| --- | --- | --- | --- | --- |
| Stage 0 | Repository skeleton | Create structure, placeholder code, synthetic samples, and documentation. | Complete | Foundation only. |
| Stage 1 | Plain text anonymization engine | Add narrow rule-based detection and label replacement for plain text. | Complete | Plain Python strings only; no file workflow. |
| Stage 2 | TXT file input/output | Read TXT files and save anonymized TXT copies. | Complete | TXT-only stage; DOCX is handled in Stage 3. |
| Stage 3 | DOCX support | Extract text from basic DOCX paragraphs and simple tables, then write an anonymized `_ANON.docx` copy. | Complete | Basic formatting only; no advanced DOCX elements. |
| Stage 4 | Text-based PDF support | Extract text from text-based PDFs and save anonymized TXT output. | Complete | No OCR, scanned PDFs, layout preservation, or anonymized PDF output. |
| Stage 5 | Simple Tkinter GUI | Add a small local desktop interface for one selected supported file. | Complete | No preview, editing, drag and drop, batch processing, OCR, or PDF writing. |
| Stage 6 | Reports without source data | Generate safe reports with labels and counts only. | Complete | No source values or replacement maps. |
| Stage 7 | Portfolio polish and release review | Review README, user docs, technical docs, existing tests, security assumptions, roadmap, and portfolio text. | Complete | Documentation and review only; no new features or scope expansion. |
| Stage 8 | Private sensitive terms dictionary | Let the user load a private local dictionary such as `term = [LABEL]`, apply longer terms first, and report only labels and counts. | Complete | Stage 8 started with literal matching only; real dictionaries must stay out of git; no replacement map or automatic entity detection. |
| Stage 9 | Post-anonymization audit | Check `_ANON` output text for conservative suspicious remaining patterns and add safe audit status and counters to the report and GUI. | Complete | Warning layer only; no guarantee of complete anonymization, source values, snippets, dictionary terms, replacement map, OCR, AI, or database. |
| Stage 10.1 | Manual validation fixes | Repair private dictionary GUI/dispatcher flow, add safe dictionary status to GUI and reports, and audit remaining loaded dictionary terms. | Complete | No OCR, AI, batch processing, database, replacement map, or output-folder workflow. |
| Stage 10.2 | Manual GUI smoke test | Confirm the dictionary path flow manually with small synthetic UTF-8 files. | Complete | Manual validation only; no new runtime features. |
| Stage 11 | Smart dictionary foundation and README polish | Add dictionary aliases, case-insensitive matching, whitespace-tolerant term matching, synthetic dictionary candidate/seed examples, focused tests, and a stronger portfolio README. | Complete | Deterministic dictionary matching only; no fuzzy matching, inflection handling, NER, OCR, AI, APIs, database, batch processing, or replacement map. |
| Stage 12 | Safe output workspace and batch processing | Let the user select multiple supported files and an output folder, save all generated files there, avoid silent overwrites with numbered names, continue after per-file errors, and write a safe batch summary report. | Complete | Sequential batch only; no drag and drop, preview, editor, OCR, AI, APIs, NER, database, or automatic approval. |
| Stage 13 | Manual review workflow | Detect generated `_ANON` outputs in an output folder, pair matching `_RAPORT` reports when present, let the user assign manual `approved`, `needs_review`, or `rejected` statuses, and save safe review status and summary metadata. | Complete | Status tracking only; no preview, editor, automatic approval, file moving, OCR, AI, APIs, local LLM, cloud service, or database. |
| Stage 15 | GUI usability cleanup | Improve GUI scaling and scrolling, show a selected-file count, clear/remove files from the GUI selection without deleting them, improve plain-language status messages, and open selected `_ANON`/matching `_RAPORT` files from manual review with the operating system default application. | Complete | Still no preview, editor, split-screen comparison, highlighting, drag and drop, OCR, AI, APIs, local LLM, NER, database, installer, or automatic approval. |
| Stage 16 | Stronger audit and review prioritization | Add conservative audit warning categories, per-file risk levels, aggregate risk counts in batch summaries, and risk display in the manual review list. | Complete | Risk is a review-prioritization helper only; no guarantee of complete anonymization, preview, editor, highlighting, OCR, AI, APIs, local LLM, NER, database, installer, or automatic approval. |
| Stage 17 | Approved workspace staging | Export only manually approved `_ANON` files from `_REVIEW_STATUS.json` into an `approved/` staging folder, optionally copy matching `_RAPORT` files, and write a safe `_APPROVED_INDEX.txt` manifest. | Complete | Staging area only; not a knowledge base, not automatic approval, not a guarantee of complete anonymization, and no OCR, AI, APIs, local LLM, NER, database, preview, editor, or installer. |
| Stage 18 | End-to-end workflow validation and MVP stabilization | Validate the complete local MVP workflow with synthetic tests and a practical manual smoke checklist: batch anonymization, safe reports, audit risk levels, manual review, approved export, and safe approved index. | Complete | Validation and documentation only; no OCR, AI, APIs, local LLM, NER, database, preview, editor, split-screen review, highlighting, drag and drop, installer, or automatic approval. |
| Stage 19 | Local OCR foundation | Add optional local OCR availability detection, image input OCR, scanned-PDF fallback when normal PDF text extraction is empty, safe OCR report metadata, safe batch OCR status, and minimal GUI file support. | Complete | Optional local OCR only; requires local OCR dependencies and Tesseract; no cloud/API OCR, OpenAI API, NER, local LLM, preview, split-screen review, highlighting, drag and drop, installer, edited image output, or anonymized PDF output. |
| Stage 20 | Local NER / NLP detection layer | Add optional local spaCy availability detection, local Polish model loading without runtime downloads, safe internal NER labels, NER integration after dictionary and regex replacements, safe NER report/batch metadata, and a minimal GUI checkbox/status path. | Complete | Optional local NER only; requires spaCy and a local Polish model; can miss or misclassify entities; no model downloads at runtime, committed model files, Ollama, Bielik, OpenAI API, cloud/API processing, online NLP, local LLM, preview, highlighting, drag and drop, database, or candidate export. |
| Stage 21 | Local LLM-assisted review layer | Add optional local Ollama availability/model handling, post-anonymization review of already-anonymized output text only, strict structured response parsing, safe LLM report/batch metadata, and minimal GUI controls. | Complete | Optional local Ollama review only; requires user-installed Ollama and a local model; no model downloads, OpenAI API, cloud/API processing, online LLMs, RAG, vector database, chat UI, document editor, document rewriting, automatic approval, or LLM-based primary anonymization. |
| Stage 22 / 22.1 | Local Knowledge Assistant MVP | Build a local `_KNOWLEDGE_INDEX.json` from manually approved anonymized `*_ANON.txt` files, chunk documents, retrieve relevant chunks with a keyword fallback, optionally use local Ollama answer generation, always show source chunk IDs, and provide CLI Ollama status/warm-up helpers for cold-start UX. | Current | Local MVP only; TXT `_ANON` inputs only; generated index must stay ignored; no embeddings, `bge-m3`, vector database, GUI, web app, OpenAI API, cloud/API processing, chat history, authentication, installer, document editor, or automatic procedure generation. |
| Later | OCR quality improvements | Improve OCR installation guidance, language configuration, error diagnostics, and manual smoke validation after the foundation is reviewed. | Not planned for MVP | Requires explicit approval and synthetic validation; OCR can remain imperfect. |
| Later | Installer | Package for easier desktop use. | Not planned for MVP | Platform-specific work. |
| Later | NER candidate export | Optionally export detected candidate terms into local generated output folders for manual dictionary review. | Not planned for MVP | Must remain gitignored and must never write candidate values to safe reports, summaries, review metadata, or approved indexes. |
| Later | Better NLP / LLM quality work | Improve detection or review quality after the current local foundations are manually validated. | Not planned for MVP | Requires explicit approval, synthetic tests, and a privacy review; no cloud/API calls or broader LLM workflow by default. |
| Later | Knowledge retrieval quality | Optionally add local embeddings such as `bge-m3:latest` after the keyword fallback is manually validated. | Not planned for MVP | Requires explicit approval, synthetic tests, generated-index safety review, and no vector database server by default. |
| Later | Stronger entity detection | Add more reliable names, addresses, organizations, and context-aware categories. | Not planned for MVP | Requires careful tests and privacy review. |
| Later | Packaging/release | Prepare distributable releases and release notes. | Not planned for MVP | Must avoid bundling private data, logs, or generated outputs. |
